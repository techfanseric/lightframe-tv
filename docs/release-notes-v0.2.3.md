# v0.2.3 · 信号源入口与自动跟随

轻幕的覆盖菜单现在认识电视的 HDMI 输入。接入的设备在应用栏里各占一个入口（浅灰底、白色苹果标记等图标），排在 YouTube 入口之后；正在播放的那个输入源不会再被重复列出。设置 → **信号源** 可以查看每个端口的接入状态并切换，当前使用的输入源由厂商接口读取，闲置端口标为未接入。

信号源也进入开机记忆：开机目标可以选择某个输入源，拔掉的设备不会把电视留在空白画面。接入设备的名字来自厂商输入列表，通用回退名称不会被当作真实设备。

声音跟随画面：接入外部设备时，Bose 音响切到它自己的 HDMI 输入；回到电视自带应用时切回电视的 ARC 通道。两者是音响上的两个不同输入，之前会切错。音响主机、端口和通道在配置时指定。

网络状态条在直连模式下显示设备总流量，而不是代理流量；此时不再显示“网络直连”几个字，节点与路线信息保持原样。状态条在 HDMI 播放时不出现。

代理模式新增三档：自动、直连、关闭。直连适合局域网路由已经做代理的场合，只探测目标站点而不要求本机 VPN；关闭则完全不探测直接打开。每个应用打开前只检查网络是否通，不再额外检查 FlClash 是否在前台。开机时若选择直连，不再强制拉起 FlClash。

Netflix 入口默认隐藏，可在设置 → **Netflix 入口** 打开，适合主要在 Apple TV 上观看的情况。

设置面板合并了“开机应用”和“开机启动”，一轮循环里多出“不自动启动”，面板回到两行。设置里的“智能家居”与应用栏上的同名入口重复，已移除；应用栏入口与面板内的“房间与全部设备”仍可使用。

版本：Home 8.9-dock (18)、Overlay 8.39-dock (49)、可选 PlaybackGuardian 2.11 (13)。并行包名与共享签名保持不变。

验证：目标电视实机覆盖升级并由用户确认信号源入口、苹果标记、Netflix 隐藏与 Bose 跟随；12 项纯 JDK 策略测试与 15 项安装器测试通过。**本轮没有执行实机冷重启**，开机记忆与冷启动路径经代码审查但未在实机上重新开机验证。真实播放、DRM 与冷启动仍需自行确认。

附件继续提供 setup/companions ZIP、TizenTube ARM32/64、FlClash ARM32/64、MyTV、可选守护、第三方来源/源码/许可证和 SHA256 校验。新增 BUILD-INFO.json 记录自有 APK 与源码提交。未包含订阅、登录数据、家庭配置或 Google 服务安装包。
